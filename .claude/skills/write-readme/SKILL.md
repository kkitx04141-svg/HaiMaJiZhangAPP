# Write README — 自动生成项目说明文档

为当前项目自动生成一份适合**编程新手**阅读的 README 文档。

## 这个技能解决什么问题

程序员写的 README 通常假设读者懂技术（"克隆仓库后 `npm install` 即可"），但很多看项目的人不是程序员。这个技能生成的 README 让**不懂编程的人也能看懂项目是做什么的、怎么用**，同时保留技术人员需要的关键信息。

## 核心原则

1. **先调查再写**：不编造项目没有的功能，所有内容基于实际文件
2. **说人话**：用普通人能理解的语言，所有技术术语第一次出现必须解释
3. **够用不啰嗦**：新人能上手就行，不需要深入技术细节
4. **不确定就标注**：拿不准的内容标注 `[待确认]`，不要硬编

## 工作流程

### 第一步：阅读项目，了解"这是什么"

按顺序检查以下内容：

1. **`README.md`（如果存在）**：了解已有内容，新 README 是在此基础上改进，不是覆盖
2. **`package.json`**：了解项目名、描述、脚本命令、依赖
3. **`CLAUDE.md` 或项目说明文件**：了解项目约定和架构
4. **入口文件**：`src/main/index.ts`（Electron）、`src/index.ts`（CLI）、`src/main.tsx`（前端）等
5. **目录结构**：`src/` 下的文件夹，了解功能模块划分
6. **配置文件**：`tsconfig.json`、`vite.config.ts` 等，了解技术栈

这一步结束后，先向用户汇报：

> 我理解这个项目是：[一句话描述]。技术栈是：[主要技术]。主要功能有：[列举]。
> 已有 README：[有/无]，包含内容：[简述]。
> 接下来我会生成一份适合新手阅读的 README。

等用户确认后再继续。

### 第二步：判断项目类型，确定要写哪些内容

根据项目类型，README 的重点不同：

| 项目类型 | 判断依据 | README 重点 |
|----------|----------|-------------|
| 桌面应用 | 有 Electron、Tauri、.exe 等 | 安装包在哪、怎么安装、怎么启动 |
| 网页应用 | 有 React/Vue/Next.js 等前端框架 | 在线地址、怎么本地运行 |
| 命令行工具 | package.json 有 `bin` 字段 | 怎么安装、常用命令 |
| 库/SDK | 有 `exports` 字段、主要给开发者用 | 怎么安装、API 怎么用 |
| 脚本/工具集 | 只有脚本文件，没有 UI | 每个脚本干什么、怎么执行 |

如果判断不了类型，直接告诉用户，不要猜。

### 第三步：生成 README

按以下结构生成，每个部分都从实际文件中提取信息。

---

## README 模板

### 1. 项目简介

```markdown
# 项目名称

[一句话说明这个项目是干什么的]

## 这是什么

[用 2-3 句话解释：什么人、在什么场景下用它、解决什么问题。避免术语。]

## 长什么样（可选）

[如果有截图，放一张主界面的截图]
```

**写法要求**：
- 让完全不懂技术的人也能理解这个项目是干什么的
- 项目名称从 `package.json` 的 `name` 或 `description` 取
- 如果 README 已有介绍，判断是否够小白友好，不够就改写

### 2. 功能特点

```markdown
## 能做什么

- **功能点 1**：一句话说明这个功能有什么用
- **功能点 2**：一句话说明这个功能有什么用
- ...
```

**写法要求**：
- 从代码中提取功能（页面组件、路由、菜单项、核心模块）
- 每个功能点用**粗体标题 + 一句话说明**的形式
- 说明功能**为用户解决什么问题**，而不是描述技术实现
- 不要列技术特性（如"使用 TypeScript"），那是"用什么做的"，不是"能做什么"

### 3. 安装步骤

```markdown
## 怎么安装

### 你需要准备

- [ ] 电脑系统：[Windows 10+ / macOS 11+ / 两者都支持]
- [ ] 需要安装：[Node.js、Git 等，如果不需要就写"无需额外安装"]
- [ ] 硬盘空间：约 [XX MB]

### 安装方法

#### 方法一：下载安装包（推荐，不需要懂代码）

1. 打开 [下载页面 / Releases 页面]
2. 下载 [文件名.exe / 文件名.dmg]
3. 双击安装
4. 安装完成后在桌面/开始菜单找到应用图标

#### 方法二：从源码运行（需要安装 Node.js）

1. 下载项目：[说明去哪下载]
2. 打开终端，进入项目文件夹
3. 安装依赖：`npm install`
4. 完成
```

**写法要求**：
- **优先提供安装包方式**（如果有），这对小白最友好
- 如果项目只有源码运行方式，安装步骤要特别详细
- `npm install` 前说清楚在哪执行（VS Code 终端？系统终端？）
- 提到可能遇到的问题（如国内网络慢），并给出解决建议
- 系统要求从 CLAUDE.md 或 electron-builder.yml 中获取

### 4. 启动命令

```markdown
## 怎么启动

### 如果用的是安装包

直接双击应用图标即可，和普通软件一样。

### 如果是从源码运行

在项目文件夹的终端中执行：

| 命令 | 作用 |
|------|------|
| `npm run dev` | 启动开发模式（边改代码边看效果） |
| `npm run build` | 编译项目 |
| `npm run package:win` | 打包成 Windows 安装程序 |
| `npm run test` | 运行测试 |

> **在哪里执行这些命令？**  
> 在 VS Code 中：菜单 → 终端 → 新建终端，然后在弹出的窗口中输入命令。
```

**写法要求**：
- 每个命令都要说明**执行后会发生什么**，不要只列命令
- 告诉用户**在哪里执行**（VS Code 终端、系统终端等）
- 如果有多种启动方式，标注哪种最简单
- 常用命令用表格展示，一目了然

### 5. 文件结构

```markdown
## 文件夹说明

给想知道"每个文件夹里是什么"的人：

\`\`\`
项目文件夹/
├── src/                     # 源代码都在这里
│   ├── main/               # Electron 主进程（窗口管理、数据库）
│   ├── renderer/           # 界面代码（你看到的页面）
│   │   ├── components/     # 可复用的界面组件
│   │   ├── pages/          # 各个页面
│   │   ├── hooks/          # 数据操作逻辑
│   │   ├── db/             # 数据库相关
│   │   └── utils/          # 工具函数
│   └── preload/            # 安全桥接层
├── dist/                   # 打包输出（安装包在这里）
├── scripts/                # 辅助脚本
├── package.json            # 项目配置文件
└── CLAUDE.md               # 项目开发说明
\`\`\`

> **如果你是普通用户**，只需要关注 `dist/` 文件夹里的安装包。其他文件夹是给开发者看的。
```

**写法要求**：
- 只列主要文件夹（不超过 10 个），不要把每个文件都列出来
- 每个文件夹用**普通人能理解的话**说明里面是什么
- 明确告诉普通用户哪些文件夹不用关心
- 结构从实际项目中读取，不要套模板

### 6. 常见问题

```markdown
## 常见问题

### 安装时提示"无法验证发布者"怎么办？

[Windows 专属问题的解决方案]

### 启动后窗口是白屏？

[可能的原因和解决方法]

### 数据存在哪里？

[数据库文件位置]

### 怎么备份数据？

[备份方法]

### 怎么卸载？

[卸载步骤]
```

**写法要求**：
- 从 CLAUDE.md 的"已知问题"部分提取
- 从项目 issue 或代码注释中找常见的坑
- 站在**新手角度**想可能遇到什么问题
- 每个问题给出**具体可操作的解决步骤**，不要只说"自行排查"
- 项目确实没有的问题不要硬编，标注 `<!-- 如有更多常见问题，欢迎补充 -->`

### 7. 技术栈（给想看技术细节的人）

```markdown
## 用什么做的

[用简单语言解释每项技术是干什么的，不要只列名词]

| 技术 | 干什么用的 |
|------|-----------|
| Electron | 把网页变成桌面应用，像微信电脑版那样 |
| React | 构建界面（你看到的按钮、列表、输入框） |
| TypeScript | 给 JavaScript 加了"类型检查"，减少 bug |
| Tailwind CSS | 写样式的工具，不用手写 CSS |
| SQLite | 数据库，数据存在你电脑上的一个文件里 |
| Vite | 编译打包工具，把代码变成能运行的文件 |
```

**写法要求**：
- 每项技术后面必须用通俗语言解释"它是干什么的"
- 如果某技术读者不需要理解，明确说明"普通用户不需要关心这个"
- 技术列表从 `package.json` 的 dependencies 中提取核心的几个

### 8. 后续优化方向

```markdown
## 后续计划

- [ ] [从代码 TODO 注释或 CLAUDE.md 中提取]
- [ ] [从项目 issue 或 roadmap 中提取]
- [ ] 更多功能欢迎提建议

> 如果你有想法，可以在 [Issues 页面 / 项目地址] 提出。
```

**写法要求**：
- 从代码中的 TODO 注释、CLAUDE.md、项目 issue 中收集
- 如果没有明确计划，写"暂无明确计划，欢迎提建议"
- 不要编造不存在的路线图

---

## 生成后的检查清单

README 写完后，逐项检查：

- [ ] 一个完全不懂技术的人能看懂"项目是干什么的"吗？
- [ ] 安装步骤在新电脑上照着做能成功吗？
- [ ] 所有命令都说明了在哪里执行吗？
- [ ] 文件夹说明和实际目录结构一致吗？
- [ ] 常见问题有具体的解决步骤吗？
- [ ] 没有编造项目不存在的功能？
- [ ] 所有技术术语第一次出现时有解释吗？
- [ ] 告诉用户哪些内容"不需要关心"了吗？

## 注意事项

1. **先读后写**：不读完项目文件不动笔
2. **保留原有 README 有用内容**：如果已有 README，取长补短，不要全部丢弃
3. **标注不确定内容**：拿不准的信息加 `[待确认]` 标记
4. **区分用户和开发者**：README 主要给用户看，开发者看 CLAUDE.md
5. **写完主动检查**：对照上述检查清单逐项自查
6. **截图可选**：如果用户要求加截图，引导用户自己截图（这个技能无法截取应用画面）
