# 注释检查技能

为"黑马记账"项目检查代码注释质量，给出改进建议。

## 检查标准

### 标准一：注释覆盖率（30% 规则）

每 10 行代码中，至少要有 3 行注释。即注释行数 / 总行数 ≥ 30%。

- 注释行：`//` 单行注释、`/** */` 文档注释、`/* */` 块注释
- 不计入注释：import 语句、空行、只有花括号的行

**关注重点**：
- ✅ 每个函数（export 或非 export）必须有注释说明"做什么"
- ✅ 每个 interface / type 定义必须有注释说明"用在哪儿"
- ✅ 核心业务逻辑（如金额转换、SQL 拼接、状态变更）必须有行内注释
- ⚠️ 明显的赋值语句（如 `const x = 1`）不强求注释

### 标准二：注释与代码一致性

注释描述的内容必须和代码实际做的事情一致。

检查要点：
- ❌ 注释说"查询全部支出"但 SQL 里有 `WHERE type = 'income'` → 不一致
- ❌ 函数名改了但注释还是旧的描述
- ❌ 注释说的参数数量和实际参数数量对不上
- ❌ 注释说"返回字符串"但实际 return 了一个数字
- ❌ 复制粘贴的注释（两个不同函数有完全相同的注释）

### 标准三：小白友好度

注释应该让非计算机专业的人也能读懂。

- ❌ "创建一个 WeakMap 实例用于存储闭包引用" — 太技术化
- ✅ "用 WeakMap 存数据，这样不用的时候浏览器会自动清理掉" — 解释了为什么
- ❌ "通过 IPC invoke 调用主进程的 dialog 模块" — 全是术语
- ✅ "弹出系统自带的文件选择窗口（通过 Electron 的 IPC 通信实现）" — 术语有解释
- ❌ 只写了"做什么"（如"格式化日期"），没写"为什么"
- ✅ 关键设计决策（如为什么用分不用元）要有注释说明原因

## 工作流程

收到用户指令后，按以下步骤执行：

### 第一步：确定检查范围

1. **用户指定了文件/目录** → 只检查指定的范围
2. **用户说"检查所有"或没指定范围** → 按优先级：
   - 优先检查 `src/renderer/utils/`（工具函数，给复用者看）
   - 其次 `src/renderer/db/`（数据操作，SQL 逻辑需要注释）
   - 再次 `src/renderer/hooks/`（状态管理逻辑）
   - 最后 `src/renderer/components/` 和 `pages/`（UI 组件）

向用户确认范围后继续。

### 第二步：逐文件检查

对每个文件，做三件事：

**（1）统计注释覆盖率**

```
总行数：X 行
注释行：Y 行
覆盖率：Y / X = Z%
是否达标：Z ≥ 30% ? ✅ : ❌
```

注意：import 块、空行、只有 `}` 的行不计入总行数。

**（2）逐函数检查注释**

每个函数检查：
- 有没有注释？没有 → 记录
- 注释内容和代码行为是否一致？不一致 → 记录
- 注释用词是否小白友好？有术语没解释 → 记录

**（3）抽查关键逻辑**

找出文件中最核心的 3-5 行代码，检查是否有行内注释解释"为什么要这么做"。

### 第三步：生成检查报告

用以下格式输出：

```
## 📝 注释检查报告

### 总体情况

| 指标 | 数值 |
|------|------|
| 检查文件数 | X 个 |
| ✅ 达标 | X 个 |
| ⚠️ 需改进 | X 个 |
| ❌ 严重不足 | X 个 |
| 总覆盖率 | X% |

### 问题清单（按严重程度排序）

#### ❌ 严重 — 缺少函数注释
| 文件 | 行号 | 问题 |
|------|------|------|
| xxx.ts | L42 | `function xxx()` 没有任何注释 |

#### ⚠️ 需改进 — 注释与代码不一致
| 文件 | 行号 | 注释写的 | 代码实际做的 |
|------|------|----------|--------------|
| xxx.ts | L15 | "查询全部" | 实际有 WHERE 过滤 |

#### ⚠️ 需改进 — 不够小白友好
| 文件 | 行号 | 原文 | 建议改为 |
|------|------|------|----------|
| xxx.ts | L8 | "IPC invoke" | "通过 Electron IPC 通信调用主进程" |

### 各文件详情

#### xxx.ts — 覆盖率 25% ⚠️
- 缺少注释的函数：`bar()`（L30）、`baz()`（L55）
- 不一致：L15 注释说"返回字符串"，实际返回 number
- 不友好：L8"IPC invoke"需要解释

### 总结

- 本次共发现 X 个问题
- 严重：X 个
- 需改进：X 个
```

## 评分规则

| 覆盖率 | 等级 |
|--------|------|
| ≥ 30% | ✅ 达标 |
| 15% ~ 29% | ⚠️ 需改进 |
| < 15% | ❌ 严重不足 |

## 注意事项

1. **关注质量而非数量**：100 行废话注释不如 10 行精准注释
2. **只看注释，不改代码**：这个技能只做检查，不修改源码，除非用户明确要求
3. **善用现有标准**：项目已有注释规范（中文注释、函数说明用 JSDoc），检查时参照这些标准
4. **类型声明文件例外**：`env.d.ts` 这类纯类型声明文件不要求注释覆盖率
